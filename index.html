03 / FROM DOWNLOAD TO FLIGHT DECK

Set up Windows, then Quest.

Before you begin

  • A Windows 11 x64 PC capable of running your own licensed X-Plane 12 and ToLiss Airbus. The current testing evidence is for ToLiss A320; other aircraft/versions require qualification.
  • Quest 3, a USB cable that carries data, and Meta Developer Mode enabled for sideloading.
  • A physical joystick connected for the virtual sidesticks. The signed neutral virtual-controller solution is not included.
  • The separate XPPanelsBridge command plugin for controls that require timed commands. Existing testers should retain their working plugin. This installer does not include or install it; a clean-PC plugin bundle is still pending.
  • Native ToLiss instrument pop-outs available for capture. A portable virtual-monitor driver is not included in this preview.

This is a testing preview for an existing supported simulator setup. It is not a complete clean-PC aircraft/plugin/driver installer. X-Plane, ToLiss, Meta and Airbus are separate products and do not endorse this project.

STEP 1

Install the Windows Companion

  1. Download the EXE and compare its SHA-256 with the release checksums.
  2. Review its self-signed status. If Windows or your organization blocks this preview, stop and use an approved deployment route; do not disable security protections.
  3. Close an older Companion before switching versions. Run the installer and select a new, empty installation folder. Administrator rights are not required.
  4. The default folder is %LOCALAPPDATA%\Programs\XPPanels Companion\0.2.0-preview.1. The installer creates XPPanels Companion Preview shortcuts and a Windows uninstall entry.
  5. Launch the Companion. It starts with sharing off and does not launch X-Plane. Keep the previous version folder as a rollback.

Only packaged files are installed. Settings and display mappings in %LOCALAPPDATA%\XPPanelsVRCompanionWindows are retained.

STEP 2

Install on Quest without the Horizon Store

  1. Follow Meta’s current Developer Mode instructions. A verified developer account may be required.
  2. Turn on the Quest, connect its USB data cable to the PC and accept Allow USB debugging inside the headset for your own computer.
  3. Download the APK and verify its checksum. The Companion includes Android platform-tools in its USBTools folder, so another ADB installation is not needed.
  4. Open PowerShell in the Companion’s installation folder and run:
.\USBTools\adb.exe devices
.\USBTools\adb.exe install -r "$env:USERPROFILE\Downloads\XPPanelsVR-Quest-2026.10.14-preview.apk"
  1. Confirm ADB reports Success. In the headset, find XPPanels Quest Foundation in Library → Unknown Sources. Meta’s exact menu labels may change.
  2. Allow the app’s hand tracking/OpenXR permissions when requested. Keep the headset awake for initial connection.

The package ID is com.aldoapps.xppanelsquest. This is a standalone native app: you do not need to run Quest Link or Air Link for its cockpit connection. Sideloading still uses Meta’s developer/USB authorization process.

If you prefer a graphical installer, use Meta Quest Developer Hub to install the same APK. Avoid running competing ADB servers.

STEP 3

Connect the cockpit over USB

  1. Start X-Plane yourself and load the supported ToLiss aircraft. Keep only one X-Plane instance running.
  2. Open the instrument pop-outs. Launch the updated Companion, select the actual running X-Plane.exe, and click Connect Cockpit.
  3. Enable Allow live cockpit controls when you are ready to use them. Controls require fresh simulator feedback.
  4. The Companion manages the two USB routes: TCP 49200 for media and 49310 for controls. Do not forward them to the internet.
  5. Look for all nine rows to report Ready in Quest. Fresh computer images and fresh headset decode reports are separate checks.
  6. If an instrument is missing, use its Repair button or Repair All Displays. Repair sends popup commands only when you request it; do this when appropriate for your flight.

MCDUs must show the LCD only, not a squashed keyboard/body. Current capture includes the crop-recovery and intermittent-stall fixes.

STEP 4

Enable the media you want

Outside view
Enable Allow outside view sharing in Companion and Outside view in the Quest menu. Leave the main X-Plane window available and unminimized. Ambiguous sources are rejected; select the ISCS source if an open dialog makes outside selection ambiguous.
Audio
Enable Allow X-Plane audio sharing, then cockpit audio in Quest. This captures X-Plane process audio, not the microphone or the whole desktop mix. A “ready” status does not replace a listening check.
ISCS on either EFB
In ToLiss Settings/Account → User Interface, enable USE POPOUT WINDOWS FOR POPUPS and SAVE POPUP CONFIG IN QUIT, then save preferences. Open and detach ISCS yourself. Enable ISCS sharing and explicitly select its window in Companion. Keep the window foreground and its touch point uncovered for clicks. Re-entering ISCS on the EFB prepares the selected source without an open/close toggle.

Update, rollback and uninstall

Download a matched pair, check hashes, close Companion, and install the new Windows version into a new folder. adb install -r updates a Quest app only if its signing identity matches. Keep your earlier installer/APK and settings backup until testing succeeds.

If Android reports INSTALL_FAILED_UPDATE_INCOMPATIBLE, do not automatically uninstall the existing app: removal can erase its local settings. Obtain a matching-key build or back up intentionally before changing signing identities. A future production-key APK may need a separate migration.

Use Windows Settings → Apps → Installed apps to uninstall this preview, or its Uninstall.exe. Uninstall preserves settings, other version folders and unrecognized files. It does not remove aircraft plugins, drivers or the Quest APK. To roll back, launch your retained previous Companion and use a matching APK.

04 / GET UNSTUCK

Check the connection, then the source.

Quest is not detected or says unauthorized

Use a data-capable cable, keep the headset awake, confirm Developer Mode, and accept USB debugging inside Quest. Check .\USBTools\adb.exe devices. Do not restart an ADB server owned by another tool during a working session.

Controls connect, but instruments are blank

Open the native pop-outs or request Repair in Companion. If Windows gives every window the same title, use the Companion’s mapping/repair workflow. An open main scenery window is not a substitute for an instrument source.

Images appear, but from the wrong display bridge

A legacy ToLissDisplayBridge simulator plugin can compete for media port 49200. Retain the separate XPPanelsBridge command plugin. Review the Companion’s source/readiness warning and resolve the competing media service deliberately; the installer never disables a plugin automatically.

Sidesticks animate but do not fly the aircraft

The current main-joystick route needs joystick hardware detected by X-Plane/ToLiss. Connect a physical joystick. Both virtual seats are independent visually but share the simulator’s main pitch/roll channels, with temporary Quest ownership and watchdog handback.

ISCS is visible in Quest, but touches do not work

ISCS must be the selected detached foreground window and its actual touch point must be uncovered. Release physical mouse buttons and keep both applications at the same privilege level. Re-select the source after closing/reopening it. Windows may deny a foreground request; bring ISCS forward yourself.

Windows reports an untrusted publisher

This free preview uses a self-signed certificate. It proves a consistent signing identity when inspected, but does not establish a publicly trusted publisher. Check checksums and the public certificate. We do not ask you to turn off SmartScreen, Smart App Control or antivirus.

What is verified—and what is still preview

The current Windows/Quest pair has offline protocol tests, installer tests and user acceptance of both-side controls. The nine instrument streams have fresh Quest telemetry. This is not broad aircraft compatibility or sustained performance qualification on every PC.

  • Windows 11 x64 and Quest 3 are the tested platform; audio needs Windows process-loopback support.
  • No bundled virtual-monitor or neutral virtual-controller driver. Hardware-free laptop operation is not complete.
  • No clean-PC command-plugin bundle yet. Preserve the working XPPanelsBridge plugin in an existing setup.
  • The Quest APK is development-signed/debuggable. The Windows certificate is self-signed and untrusted by default.
  • Preview for personal entertainment and testing, not real aviation or certified flight training.
