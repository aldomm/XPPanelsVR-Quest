03 / FROM DOWNLOAD TO FLIGHT DECK

Set up your computer, then Quest.

Follow these steps in order on your own setup. First install Companion and its command plugin with X-Plane closed, then install the Quest beta, connect USB and run the first-flight checks. Keep any working installation as rollback.

Before you begin

  • A Windows 11 x64 PC or Apple-silicon Mac with macOS 15 or later, capable of running your own licensed X-Plane 12 and ToLiss Airbus. The current testing evidence is for ToLiss A320; other aircraft/versions require qualification.
  • Quest 3 or 3S, a Meta account linked to the headset, and a USB cable that carries data.
  • Meta Developer Mode and USB debugging are still required for the Companion’s USB forwarding even though Meta now installs the headset app.
  • A physical joystick connected for the virtual sidesticks. The signed neutral virtual-controller solution is not included.
  • The XPPanelsBridge command plugin for timed controls. The Mac Companion includes a guided plugin installer. Windows Companion 0.2.1-beta.1 also bundles guided command-plugin setup; install/update it explicitly with X-Plane closed.
  • Native ToLiss instrument pop-outs available for capture. Windows uses your existing display setup and has no bundled virtual-monitor driver yet. The Mac Companion includes an optional integrated virtual monitor; see the Mac instructions below.

This is a public beta for an existing supported simulator setup. It is not a complete aircraft, simulator or driver installer. X-Plane, ToLiss, Meta and Airbus are separate products and do not endorse this project.

STEP 1

Install the Windows Companion

  1. Download the EXE and compare its SHA-256 with the release checksums.
  2. Review its self-signed status. If Windows or your organization blocks this beta, stop and use an approved deployment route; do not disable security protections.
  3. Close an older Companion before switching versions. Run the installer and select a new, empty installation folder. The Companion application installs per user without administrator rights. Your X-Plane plugin folder must also be writable; if it is protected, have your administrator install the plugin rather than changing folder permissions.
  4. The default folder is %LOCALAPPDATA%\Programs\XPPanels Companion\0.2.1-beta.1. The installer creates XPPanels Companion Preview shortcuts and a Windows uninstall entry.
  5. Launch the Companion and choose your X-Plane.exe. To install the command plugin, disconnect Cockpit and quit all X-Plane instances, then choose Check plugin → Install / Update Plugin. Confirm the action. Recognized existing plugins receive a verified backup.
  6. Wait for “Plugin installed. Start X-Plane to load it.” If plugin setup refuses a custom or modified plugin, keep a manual backup and contact support instead of deleting unknown files. Start X-Plane yourself afterward. Companion starts with sharing off and does not launch the simulator. Keep the previous Companion folder as rollback.

The EXE installer installs Companion only; plugin setup runs separately when you request it. Use Restore Previous Plugin or Remove Plugin with X-Plane closed. Removal requires an intact managed receipt. Modified plugins, unknown/custom files, links and junctions are refused. Verified backups live in %LOCALAPPDATA%\XPPanelsVRCompanionWindows\PluginBackups. Existing settings and display mappings are retained.

STEP 1B · macOS

Install the Mac Companion

  1. Download the PKG and compare its SHA-256 with the release checksums. pkgutil --check-signature should report a Developer ID Installer identity and trusted Apple notarization.
  2. Quit X-Plane and any older Companion. Open the PKG and install XPPanelsVR Companion in Applications. The package is for Apple-silicon Macs running macOS 15 or later.
  3. Open Companion from Applications. Grant Screen & System Audio Recording when requested; restart Companion after macOS asks. Accessibility is needed for automatic pop-out placement and ISCS click forwarding. Local Network is used only for an explicitly approved private-LAN fallback.
  4. In Companion Setup, select your X-Plane folder and choose Install / Update Plugin. The included XPPanelsBridge is backed up and replaced through the guided installer; restart X-Plane afterward.
  5. For an optional Mac virtual monitor, create XPPanelsVR Outside in Companion before starting X-Plane. In X-Plane Graphics, select that display for the main scenery view. Keep it attached throughout the flight and quit X-Plane before removing it. You can instead use an existing display.
  6. Keep the previous installer as rollback until the Mac, Quest and simulator have passed your checks. Use this page’s Quest-compatible Mac PKG, rather than substituting an older Vision Pro Companion download.

The package installs only /Applications/XPPanelsVR Companion.app. It does not install X-Plane, ToLiss, a virtual controller or the Quest APK.

STEP 2

Install from the Meta-managed Beta

  1. Open the XPPanelsVR private Beta invitation while signed in to the Meta account linked to your Quest.
  2. Confirm you are at least 18, accept Meta’s release-channel terms and press Join release channel. The request initially shows Pending approval.
  3. Wait for AldoApps to approve the request. Reload the invitation page after approval and press Install on device. Select your Quest if Meta asks.
  4. Keep the headset powered and online while Meta installs XPPanelsVR for Quest. Future channel builds update through Meta and the channel requires its latest build.
  5. For the Companion connection, enable Developer Mode, connect the USB data cable and accept Allow USB debugging inside the headset for your own computer. Keep Quest awake during first connection. If authorization is missing, unplug/reconnect USB and check inside the headset; a charging-only cable will not work.
  6. Launch XPPanelsVR from the Quest Library and allow hand-tracking/OpenXR permissions when requested. Quest Link or Air Link is not used.

The package ID is com.aldoapps.xppanelsquest. The Meta build is non-debuggable, production-signed and supports Quest 3/3S. An older direct development APK cannot update in place because its signing certificate differs; back up any settings and uninstall it once before the Meta build.

Direct APK fallback for development

The GitHub release retains the accepted development-signed APK for technical fallback. It requires manual checksum verification, Developer Mode and ADB installation, appears under Unknown Sources, and cannot update the Meta-signed build. Use only one signing channel at a time.

STEP 3

Connect the cockpit over USB

  1. Start X-Plane yourself and load the supported ToLiss aircraft. Keep only one X-Plane instance running.
  2. Open and detach the nine ToLiss instrument pop-outs: Captain PFD/ND, First Officer PFD/ND, upper/lower ECAM, MCDU 1/2 and ISIS. Keep source windows available and unminimized. On Windows, select the running X-Plane.exe and click Connect Cockpit. On Mac, confirm the X-Plane folder/plugin in Setup, then start sharing and connect the cockpit.
  3. Enable Allow live cockpit controls when you are ready to use them. Controls require fresh simulator feedback.
  4. Keep the desktop Companion and the native Quest app open for the whole session. If multiple headsets are attached, select your intended device in Companion. The Companion manages the two USB routes: TCP 49200 for media and 49310 for controls. Do not forward them to the internet.
  5. Look for all nine rows to report Ready in Quest. Fresh computer images and fresh headset decode reports are separate checks.
  6. If an instrument is missing, use its Repair button or Repair All Displays. Repair sends popup commands only when you request it; do this when appropriate for your flight.

MCDUs must show the LCD only, not a squashed keyboard/body. Current capture includes the crop-recovery and intermittent-stall fixes.

If the status says Quest source unverified, wait for connection to settle. If it persists and a legacy ToLissDisplayBridge plugin is enabled, use X-Plane’s Plugin Admin to disable only that media plugin. Keep XPPanelsBridge enabled: it handles cockpit commands. Do not run a separate legacy bridge/helper beside Companion.

STEP 4

Enable the media you want

Outside view
Enable Allow outside view sharing in Companion and Outside view in the Quest menu. Leave the main X-Plane window available and unminimized. On Windows this beta uses H.264 Economy (up to 2560 × 720, 30 source fps); higher-quality modes and a managed virtual monitor are not included. Ambiguous sources are rejected; select the ISCS source if an open dialog makes outside selection ambiguous.
Audio
Enable Allow X-Plane audio sharing, then cockpit audio in Quest. This captures X-Plane process audio, not the microphone or the whole desktop mix. A “ready” status does not replace a listening check.
ISCS on either EFB
In ToLiss Settings/Account → User Interface, enable USE POPOUT WINDOWS FOR POPUPS and SAVE POPUP CONFIG IN QUIT, then save preferences. Open and detach ISCS yourself. Enable ISCS sharing and explicitly select its window in Companion. Open ISCS on the desired EFB in Quest. Keep the desktop ISCS window foreground and its touch point uncovered for clicks; a hidden or covered window cannot receive reliable mapped touches. With X-Plane full screen, bring the detached ISCS window forward yourself if Windows denies the foreground request. Re-entering ISCS on the EFB prepares the selected source without an open/close toggle.

STEP 5

Check your first session

  1. Park safely before trying controls. Confirm Companion reports a fresh control session and all nine rows say Ready in Quest.
  2. Inside Quest, check that each instrument updates and that both MCDUs show only their LCD area. Computer readiness alone does not prove that you see the correct image.
  3. Try one suitable Captain and one First Officer control, check that X-Plane responds, and return both to their original settings.
  4. If enabled, check that scenery updates, listen for X-Plane sound, and test a harmless ISCS page change from the EFB. Keep its detached desktop window foreground.
  5. If USB drops, keep Quest awake, reconnect the cable and follow Companion’s recovery/authorization status. If one display remains missing, use its individual Repair; use Repair All Displays only when appropriate for your flight.

Confirmed on the development Windows 11 / ToLiss A320 / Quest 3 setup on 15 October 2026: plugin installation and loading, Captain and First Officer controls, ISCS and audio with Meta beta build 20002. All nine streams also passed fresh capture and Quest decode checks. This is a sampled acceptance pass, not a guarantee for every computer or aircraft version.

Update, rollback and uninstall

Download a matched Companion, check its hash and close the older Companion. On Windows, install the new version into a new folder. On Mac, quit X-Plane and Companion, then run the signed PKG; it upgrades the application in place. The Meta Beta updates the Quest app through Meta and requires channel members to use its latest build.

The first move from the direct development APK to the production-signed Meta build requires one intentional uninstall because Android will not mix signing identities. Removal can erase local headset settings. After migration, stay on the Meta channel; do not install the differently signed direct APK over it.

On Windows, optionally restore/remove the managed plugin in Companion first with X-Plane closed, then use Settings → Apps → Installed apps or Uninstall.exe. Uninstalling Companion does not remove the simulator plugin or its backups. On Mac, first remove the plugin through Companion Setup if desired, then quit the app and move it from Applications to Trash. Saved computer settings, logs and plugin backups remain until removed separately. Neither method removes the Quest app.

04 / GET UNSTUCK

Check the connection, then the source.

Quest is not detected or says unauthorized

Use a data-capable cable, keep the headset awake, confirm Developer Mode, and accept USB debugging inside Quest. Both Companions include ADB; no separate Android SDK installation is required. On Windows, the device ID from Companion can be entered in its optional Quest device field if more than one headset is attached. Do not restart an ADB server owned by another tool during a working session.

Controls connect, but instruments are blank

Open the native pop-outs or request Repair in Companion. If Windows gives every window the same title, use the Companion’s mapping/repair workflow. An open main scenery window is not a substitute for an instrument source.

Images appear, but from the wrong display bridge

A legacy ToLissDisplayBridge simulator plugin can compete for media port 49200. Retain the separate XPPanelsBridge command plugin. Review the Companion’s source/readiness warning and resolve the competing media service deliberately; the installer never disables a plugin automatically.

Sidesticks animate but do not fly the aircraft

The current main-joystick route needs joystick hardware detected by X-Plane/ToLiss. Connect a physical joystick. Both virtual seats are independent visually but share the simulator’s main pitch/roll channels, with temporary Quest ownership and watchdog handback.

ISCS is visible in Quest, but touches do not work

ISCS must be the selected detached foreground window and its actual touch point must be uncovered. Release physical mouse buttons and keep both applications at the same privilege level. Re-select the source after closing/reopening it. Windows may deny a foreground request; bring ISCS forward yourself.

Windows reports an untrusted publisher

This free beta uses a self-signed certificate. It proves a consistent signing identity when inspected, but does not establish a publicly trusted publisher. Check checksums and the public certificate. We do not ask you to turn off SmartScreen, Smart App Control or antivirus.

Mac cannot capture or operate simulator windows

In System Settings → Privacy & Security, allow Screen & System Audio Recording for display capture and Accessibility for automatic window placement and ISCS clicks. Restart Companion after changing permissions. The PKG itself should report a Developer ID Installer signature and Apple notarization; do not disable Gatekeeper.

What is verified—and what remains beta

The accepted cockpit baseline has user acceptance of both-side controls on the development Mac and Windows systems. Windows 0.2.1-beta.1 plugin installation/loading and both-side sampled controls were verified with Meta beta code 20002 on 15 October 2026; the user also confirmed ISCS and audio. All nine instrument streams passed fresh capture and Quest decode checks. The Mac 0.2.0-beta.1 package retains the accepted Mac/Quest baseline and is Apple-notarized; clean-Mac installation and a second Mac/headset remain unqualified. This is not broad aircraft compatibility or sustained performance qualification on every PC.

  • Windows 11 x64 or Apple-silicon macOS 15+, plus Quest 3, are the tested platforms. Quest 3S is enabled in Meta but has not received a separate physical acceptance pass. Intel Mac is not included.
  • Windows has no bundled virtual-monitor driver; portable hardware-free laptop operation is not complete. Mac has an optional integrated virtual monitor. Neither download includes a neutral virtual-controller driver; keep a physical joystick connected.
  • Both Companions include guided XPPanelsBridge setup. Windows 0.2.1-beta.1 adds plugin setup while preserving the accepted Economy streaming and cockpit protocols.
  • The primary Quest Beta is production-signed and Meta-managed. Windows is self-signed and untrusted by default; Mac is Developer ID signed and notarized.
  • Public beta for personal entertainment and testing, not real aviation or certified flight training.
