Before you begin

  • A Windows 11 x64 PC or Apple-silicon Mac with macOS 15 or later, capable of running your own licensed X-Plane 12 and ToLiss Airbus. The current testing evidence is for ToLiss A320; other aircraft/versions require qualification.
  • Quest 3, a USB cable that carries data, and Meta Developer Mode enabled for sideloading.
  • A physical joystick connected for the virtual sidesticks. The signed neutral virtual-controller solution is not included.
  • The XPPanelsBridge command plugin for timed controls. The Mac Companion includes a guided plugin installer. Windows testers must retain their separate working plugin because the Windows installer does not currently bundle it.
  • Native ToLiss instrument pop-outs available for capture. A portable cross-platform virtual-monitor driver is not included in this beta.

This is a public beta for an existing supported simulator setup. It is not a complete aircraft, simulator or driver installer. X-Plane, ToLiss, Meta and Airbus are separate products and do not endorse this project.

STEP 1

Install the Windows Companion

  1. Download the EXE and compare its SHA-256 with the release checksums.
  2. Review its self-signed status. If Windows or your organization blocks this beta, stop and use an approved deployment route; do not disable security protections.
  3. Close an older Companion before switching versions. Run the installer and select a new, empty installation folder. Administrator rights are not required.
  4. The default folder is %LOCALAPPDATA%\Programs\XPPanels Companion\0.2.0-preview.1. This Beta 1 promotion keeps that internal folder name because the flight-tested installer binary is unchanged. The installer creates XPPanels Companion Preview shortcuts and a Windows uninstall entry.
  5. Launch the Companion. It starts with sharing off and does not launch X-Plane. Keep the previous version folder as a rollback.

Only packaged files are installed. Settings and display mappings in %LOCALAPPDATA%\XPPanelsVRCompanionWindows are retained.

STEP 1B · macOS

Install the Mac Companion

  1. Download the PKG and compare its SHA-256 with the release checksums. pkgutil --check-signature should report a Developer ID Installer identity and trusted Apple notarization.
  2. Quit X-Plane and any older Companion. Open the PKG and install XPPanelsVR Companion in Applications. The package is for Apple-silicon Macs running macOS 15 or later.
  3. Open Companion from Applications. Grant Screen & System Audio Recording when requested; restart Companion after macOS asks. Accessibility is needed for automatic pop-out placement and ISCS click forwarding. Local Network is used only for an explicitly approved private-LAN fallback.
  4. In Companion Setup, select your X-Plane folder and choose Install / Update Plugin. The included XPPanelsBridge is backed up and replaced through the guided installer; restart X-Plane afterward.
  5. Keep the previous installer as rollback until the Mac, Quest and simulator have passed your checks.

The package installs only /Applications/XPPanelsVR Companion.app. It does not install X-Plane, ToLiss, a virtual controller or the Quest APK.

STEP 2

Install on Quest without the Horizon Store

  1. Follow Meta’s current Developer Mode instructions. A verified developer account may be required.
  2. Turn on the Quest, connect its USB data cable to the computer and accept Allow USB debugging inside the headset for your own computer.
  3. Download the APK and verify its checksum. Both Companions include Android platform-tools, so another ADB installation is not needed.
  4. Run the commands for your computer:

Windows PowerShell

.\USBTools\adb.exe devices
.\USBTools\adb.exe install -r "$env:USERPROFILE\Downloads\XPPanelsVR-Quest-2026.10.14-beta.1.apk"

macOS Terminal

ADB="/Applications/XPPanelsVR Companion.app/Contents/Resources/USBTools/adb"
"$ADB" devices
"$ADB" install -r ~/Downloads/XPPanelsVR-Quest-2026.10.14-beta.1.apk
  1. Confirm ADB reports Success. In the headset, find XPPanels Quest Foundation in Library → Unknown Sources. Meta’s exact menu labels may change.
  2. Allow the app’s hand tracking/OpenXR permissions when requested. Keep the headset awake for initial connection.

The package ID is com.aldoapps.xppanelsquest. This is a standalone native app: you do not need to run Quest Link or Air Link for its cockpit connection. Sideloading still uses Meta’s developer/USB authorization process.

If you prefer a graphical installer, use Meta Quest Developer Hub to install the same APK. Avoid running competing ADB servers.

STEP 3

Connect the cockpit over USB

  1. Start X-Plane yourself and load the supported ToLiss aircraft. Keep only one X-Plane instance running.
  2. Open the instrument pop-outs. On Windows, select the running X-Plane.exe and click Connect Cockpit. On Mac, confirm the X-Plane folder/plugin in Setup, then start sharing and connect the cockpit.
  3. Enable Allow live cockpit controls when you are ready to use them. Controls require fresh simulator feedback.
  4. The Companion manages the two USB routes: TCP 49200 for media and 49310 for controls. Do not forward them to the internet.
  5. Look for all nine rows to report Ready in Quest. Fresh computer images and fresh headset decode reports are separate checks.
  6. If an instrument is missing, use its Repair button or Repair All Displays. Repair sends popup commands only when you request it; do this when appropriate for your flight.

MCDUs must show the LCD only, not a squashed keyboard/body. Current capture includes the crop-recovery and intermittent-stall fixes.

STEP 4

Enable the media you want

Outside view
Enable Allow outside view sharing in Companion and Outside view in the Quest menu. Leave the main X-Plane window available and unminimized. Ambiguous sources are rejected; select the ISCS source if an open dialog makes outside selection ambiguous.
Audio
Enable Allow X-Plane audio sharing, then cockpit audio in Quest. This captures X-Plane process audio, not the microphone or the whole desktop mix. A “ready” status does not replace a listening check.
ISCS on either EFB
In ToLiss Settings/Account → User Interface, enable USE POPOUT WINDOWS FOR POPUPS and SAVE POPUP CONFIG IN QUIT, then save preferences. Open and detach ISCS yourself. Enable ISCS sharing and explicitly select its window in Companion. Keep the window foreground and its touch point uncovered for clicks. Re-entering ISCS on the EFB prepares the selected source without an open/close toggle.

Update, rollback and uninstall

Download a matched pair, check hashes and close Companion. On Windows, install the new version into a new folder. On Mac, quit X-Plane and Companion, then run the signed PKG; it upgrades the application in place. adb install -r updates a Quest app only if its signing identity matches. Keep your earlier installer/APK and settings backup until testing succeeds.

If Android reports INSTALL_FAILED_UPDATE_INCOMPATIBLE, do not automatically uninstall the existing app: removal can erase its local settings. Obtain a matching-key build or back up intentionally before changing signing identities. A future production-key APK may need a separate migration.

On Windows, use Settings → Apps → Installed apps or Uninstall.exe. On Mac, first remove the plugin through Companion Setup if desired, then quit the app and move it from Applications to Trash. Saved settings, logs and plugin backups remain until removed separately. Neither method removes the Quest APK. To roll back, use your retained previous Companion installer with a matching APK.

04 / GET UNSTUCK

Check the connection, then the source.

Quest is not detected or says unauthorized

Use a data-capable cable, keep the headset awake, confirm Developer Mode, and accept USB debugging inside Quest. Check adb devices with the bundled tool using the commands above. Do not restart an ADB server owned by another tool during a working session.

Controls connect, but instruments are blank

Open the native pop-outs or request Repair in Companion. If Windows gives every window the same title, use the Companion’s mapping/repair workflow. An open main scenery window is not a substitute for an instrument source.

Images appear, but from the wrong display bridge

A legacy ToLissDisplayBridge simulator plugin can compete for media port 49200. Retain the separate XPPanelsBridge command plugin. Review the Companion’s source/readiness warning and resolve the competing media service deliberately; the installer never disables a plugin automatically.

Sidesticks animate but do not fly the aircraft

The current main-joystick route needs joystick hardware detected by X-Plane/ToLiss. Connect a physical joystick. Both virtual seats are independent visually but share the simulator’s main pitch/roll channels, with temporary Quest ownership and watchdog handback.

ISCS is visible in Quest, but touches do not work

ISCS must be the selected detached foreground window and its actual touch point must be uncovered. Release physical mouse buttons and keep both applications at the same privilege level. Re-select the source after closing/reopening it. Windows may deny a foreground request; bring ISCS forward yourself.

Windows reports an untrusted publisher

This free beta uses a self-signed certificate. It proves a consistent signing identity when inspected, but does not establish a publicly trusted publisher. Check checksums and the public certificate. We do not ask you to turn off SmartScreen, Smart App Control or antivirus.

Mac cannot capture or operate simulator windows

In System Settings → Privacy & Security, allow Screen & System Audio Recording for display capture and Accessibility for automatic window placement and ISCS clicks. Restart Companion after changing permissions. The PKG itself should report a Developer ID Installer signature and Apple notarization; do not disable Gatekeeper.

What is verified—and what remains beta

The current Windows/Mac/Quest builds have offline protocol tests, installer/signature checks and user acceptance of both-side controls on the development Mac and Windows systems. The nine instrument streams have fresh Quest telemetry. This is not broad aircraft compatibility or sustained performance qualification on every PC.

  • Windows 11 x64 or Apple-silicon macOS 15+, plus Quest 3, are the tested platforms. Intel Mac is not included in this package.
  • No bundled virtual-monitor or neutral virtual-controller driver. Hardware-free laptop operation is not complete.
  • Mac includes guided XPPanelsBridge installation. Windows still needs the separate working command plugin.
  • The Quest APK is development-signed/debuggable. Windows is self-signed and untrusted by default; Mac is Developer ID signed and notarized.
  • Public beta for personal entertainment and testing, not real aviation or certified flight training.
